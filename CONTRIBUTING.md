# Contributing to Life OS

Life OS is a local-first project for turning daily activity into careful, reviewable observations.

## Development flow

1. Create a focused branch for one change.
2. Keep behavior changes small and explain the reason for them.
3. Add or update tests when changing validation, storage, or API behavior.
4. Run the test suite locally before opening a pull request.
5. Describe what changed and how you verified it.

## Data and privacy

Life OS is intended to keep personal activity data local. Do not commit personal logs, databases, credentials, API keys, or other private data to the repository.

## Product principle

Prefer measurements and transparent calculations over unsupported claims. Correlation is an observation, not proof of causation.

## Pull requests

A good pull request should have a clear title, a short problem statement, the implemented change, and verification notes. Documentation-only improvements are welcome when they make the project easier to understand or use.
